# 数据库基础

本文件是课程 RAG 项目的离线评估语料。它介绍关系型数据库的常用概念，供检索评估使用。

## PostgreSQL

PostgreSQL 是一个开源的关系型数据库。它用表存储结构化数据，用 SQL 描述查询。

PostgreSQL 支持事务、约束、视图和丰富的数据类型，常用于存放用户、课程和订单数据。

PostgreSQL 允许通过扩展增加能力。扩展在数据库层面注册，不需要修改应用代码。

本项目当前没有使用 PostgreSQL。检索索引仍然保存在内存里，重启后需要重新构建。

连接数据库需要地址、端口、库名和账号密码。这些配置属于环境变量，不应该写进代码仓库。

## 主键与外键

主键唯一标识表里的一行。它的值不允许重复，也不允许为空。

外键指向另一张表的主键。它表达"这一行属于那一行"这种从属关系。

外键约束由数据库强制执行。插入一个不存在的引用时，数据库会直接拒绝写入。

主键管的是本表内部的唯一性，外键管的是两张表之间的一致性，两者解决的问题不同。

自增整数和 UUID 都可以做主键。自增列有序且紧凑，UUID 便于在写入前生成。

## CRUD

CRUD 指创建、读取、更新和删除四种基本操作。它们对应 SQL 的 INSERT、SELECT、UPDATE 和 DELETE。

更新和删除必须带上明确的 WHERE 条件。漏写条件会影响整张表的全部数据。

读取通常是最高频的操作。大部分性能优化工作都集中在查询路径上。

软删除用一个标记列表示记录已失效，而不是真正删掉。它便于追溯，但每条查询都要记得过滤。

## 事务

事务把多条语句打包成一个整体。要么全部生效，要么全部回滚。

转账是最常见的例子。扣款成功而入账失败时，事务回滚可以避免账目对不上。

事务提交之后修改才真正持久化。提交之前的修改对其他会话不可见。

失败时回滚，成功时提交。让数据在任何一个中间步骤崩溃后都不会停在不一致状态。

事务应该尽量短。长事务会长期持有资源，拖慢其他会话，也更容易互相等待。

## 索引

索引是为加速查询建立的额外数据结构。它让数据库不必逐行扫描整张表。

索引会加快读取，但会拖慢写入。每次插入和更新都要同步维护索引。

索引不是越多越好。很少被用到的索引只会占用空间并增加写入成本。

区分度低的列不适合单独建索引。例如只有两种取值的状态列，索引带来的收益很有限。

多列索引的列顺序很重要。只用到后面的列时，这个索引往往用不上。

主键会自动带一个唯一索引。外键列则通常需要自己补上索引。

## SQL JOIN

JOIN 把多张表按关联条件拼接成一个结果集。最常见的关联条件是外键等于主键。

INNER JOIN 只保留两边都能匹配上的行。匹配不上的行会被丢弃。

LEFT JOIN 保留左表的全部行。右表没有匹配时，右侧字段填充为 NULL。

JOIN 的关联列上通常需要索引。缺少索引时，连接大表会非常慢。

一次连接过多的表会让查询计划变复杂。必要时可以拆成多次查询，在应用层组装。

## Repository 与数据库访问

Repository 层是应用访问数据库的唯一入口。SQL 只出现在这一层。

把 SQL 分散到 Service 或 Router 中，会让存储细节泄漏到业务代码里。

Repository 层返回领域对象，而不是数据库游标或原始行元组。

事务边界通常由 Service 层决定。Repository 只在给定的事务里执行读写。

## pgvector 的定位

pgvector 是 PostgreSQL 的一个向量扩展。它增加向量列类型和向量距离运算。

pgvector 让向量和业务数据保存在同一个数据库里，检索和过滤可以写在同一条 SQL 中。

pgvector 属于备选方案，本项目目前没有引入它，也没有使用任何外部向量数据库。

选择向量存储时要考虑数据规模、并发和运维成本，而不是只看功能列表。

把向量放进关系型数据库的好处是运维统一。代价是超大规模场景下的检索性能可能不如专用引擎。
