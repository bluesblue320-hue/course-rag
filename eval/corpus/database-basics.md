# 数据库基础

## PostgreSQL 概述

PostgreSQL 是开源的关系型数据库，支持结构化数据持久化，例如用户、课程、订单等表格数据。关系型数据库把数据组织成表，表由行和列构成。PostgreSQL 支持 SQL 查询、事务、约束和扩展，是课程项目中推荐的存储方案。

## 主键与外键

主键用于唯一标识表中的一行记录，主键列的值不能重复，也不能为空。外键用于表达表与表之间的引用关系，例如订单表中的用户编号引用用户表的主键。外键约束保证引用完整性：被引用的记录存在时才能建立关联，删除被引用的记录时数据库会按规则处理。主键与外键是把数据拆成多张表后保持关系一致的基础。

## CRUD

CRUD 指创建、读取、更新和删除四种基本数据操作。创建对应 INSERT，读取对应 SELECT，更新对应 UPDATE，删除对应 DELETE。分层项目中的 Repository 层把这四种操作封装成接口，Service 层通过接口使用数据，不直接书写 SQL 语句。CRUD 接口的命名应当表达业务含义，而不是暴露具体 SQL。

## 事务

事务把一组数据库操作绑定成一个整体，要么全部成功，要么全部回滚。事务的四个特性通常称为 ACID：原子性、一致性、隔离性和持久性。写事务需要先提交，提交成功后才对其他会话可见；如果中途失败，可以回滚到事务开始前的状态。需要同时修改多张表的业务操作应当放在同一个事务中。

## 索引

索引用于加速查询，避免每次查找都扫描整张表。创建索引时需要考虑查询模式：频繁出现在 WHERE 条件或 JOIN 键上的列适合建立索引。索引不是越多越好，写入时需要同步维护索引，过多的索引会拖慢更新操作。索引能加速查询，但不会改变查询结果。

## SQL JOIN

JOIN 用于把多张表的数据按关联条件合并成结果集。内连接只返回两边都能匹配的记录，左连接会保留左侧表的全部记录，右侧没有匹配时对应字段为空。JOIN 的关联条件通常写在主键与外键之间。在分层项目中，复杂的 JOIN 查询封装在 Repository 层，由它决定查询边界和返回结构。

## Repository 与数据库访问

Repository 层与数据库交互时，应当把数据库异常转换成领域异常，而不是把底层错误直接抛给上层。数据库连接、事务边界和查询语句都属于 Repository 的实现细节。这样 Service 层才能在不依赖数据库的情况下被测试，也方便后续替换存储实现。

## pgvector 的定位

pgvector 是 PostgreSQL 的扩展，为关系数据库增加向量列和向量相似度检索能力。它让同一套数据库既能存结构化数据，也能存 Embedding 向量。pgvector 属于存储与检索基础设施，与本项目的关系是：如果项目后续引入向量数据库，pgvector 是候选方案之一。当前项目没有使用 pgvector，检索基于内存索引实现。
